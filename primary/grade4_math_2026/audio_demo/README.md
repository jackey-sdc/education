# 讲解语音自然度：问题定位、方案调研与试听 Demo

> 目标：把「像念稿」的机器音，换成「像老师在讲」的声音。
> 本目录只做验证，不改动现有课件；确认后再接入。

打开 `index.html` 即可试听（离线、双击打开）。

---

## 一、现在为什么生硬

不是「语速没调好」，是三个独立问题叠在一起：

| # | 病根 | 具体表现 | 本机证据（已实测） |
|---|---|---|---|
| ① | **引擎** | 浏览器 `speechSynthesis` 调的是系统规则合成语音，逐字拼接、无句调曲线，数字念得像报数 | Chrome 暴露 **21 个中文语音名**（婷婷、语舒、Eddy、Flo、Grandma…），但 `say` 渲染出来**逐字节相同（md5 一致）**——21 个名字指向同一档合成引擎，换名字不换声音。演示里的 `a2_yushu` 就是这条陷阱的证据 |
| ② | **断句** | 停顿全靠标点让引擎自己猜，句与句之间没有换气位置 | 现有实现按字数估时长（`n * 300 / rate + 700`），从来没有真实的停顿控制 |
| ③ | **文案** | 脚本是书面语，没有对象感、没有设问 | 例：「选一格代表 5 人，纵轴画到 30 就够了。」——谁念都像稿子 |

**结论：换引擎只能解决 ①。②③ 不解决，仍然是「清晰的机器音」。**

## 二、网上有哪些办法（按质量/成本排序）

### 1. 神经语音云接口

| 方案 | 中文质量 | 成本 | 是否需要部署 | 备注 |
|---|---|---|---|---|
| **Edge TTS**（本 demo 采用） | 好 | **免费** | 无需部署，pip 一个包 | 音色与微软 Azure 语音服务同名同源；走的是朗读接口，属社区方案，**正式出版应改走 Azure 商用接口** |
| 火山引擎 / 讯飞 | 中上 | 按字数计费 | 需备案与密钥 | 稳定、有商用资质 |
| MiniMax | 好（情感强） | 按字数计费 | 需密钥 | 该账号已在用，可顺带接入 |
| Azure 语音服务 | 好（同样音色） | 按字数计费 | 需密钥 | Edge 音色的合规版本 |

### 2. 本地开源模型

| 方案 | 中文质量 | 代价 |
|---|---|---|
| **CosyVoice 2 / 300M** | 第三方测评中最高 | 需 Python 环境 + 显存/内存 1.4GB 起；可零样本克隆 |
| ChatTTS | 对话感强 | 本地部署，情感可控性一般 |
| GPT-SoVITS / F5-TTS | 可克隆特定老师声音 | 需要训练/参考音频，最重 |

### 3. 第三方测评数据（**非官方，仅作横向参考**）

- 《AI工具宝箱》2026 年实测，5 款工具各合成 5 万字、3 人盲听打分：
  CosyVoice **8.7** > Fish Audio 8.4 > ElevenLabs v3 7.8 > 火山引擎 7.5 > **Edge TTS 7.1**
- CSDN 实测（同一句对比）：CosyVoice2-0.5B **4.7/5** > 商用克隆 API 4.3 > **Edge TTS 3.2/5**
- CSDN 另一组（CPU 部署对比）：CosyVoice-300M Lite **4.7** > VITS-CPU 3.9 > Edge-TTS 3.5

**三份测评口径不同、分数不可直接比大小，但方向一致：CosyVoice 一类本地大模型 > 云接口 > Edge TTS > 系统合成语音。**
Edge TTS 的价值不在「最好」，而在**零成本、零部署、当天能上线**。

## 三、本 Demo 验证了三个杠杆

同一句讲解词，只改一个变量：

| 组 | 对比 | 变量 |
|---|---|---|
| ① 引擎 | `a0_system` → `a1_xiaoxiao` | 只换引擎（`a2_yushu` 是「换名字不换声音」的陷阱样本） |
| ② 调法 | `b2_teach_noPau` → `b1_teach` | 只加句读留白（逗号 300ms / 句号 620ms） |
| ② 调法 | `b3_emp_off` → `b4_emp_on` | 只加「关键数字降速 26% + 后移 200ms」 |
| ③ 音色 | `c1/c2/c3` | 男声活泼 / 男声稳重 / 女声轻快 |
| ④ 文案 | `d1_book` → `d2_spoken` | 只把书面语改成口语 |
| ⑤ 连贯 | `e1` → `e2` | 长段落整体听 |

**收益排序（按试听判断，非实验室数据）：文案 > 引擎 > 留白 > 重读 > 音色。**

关键点：**重音必须人工标**。神经语音不会自动知道「5 格多一点」是这句话的重点，
现在的做法是给脚本加一个 `emp` 字段列出重点短语，生成时对这些片段单独降速、前后加白。

## 四、工程化落地方案（推荐 A）

### A. 预生成音频 + `<audio>` 播放（推荐）

```
narr.js（含 say / sub / act / emp）
      ↓  build 阶段：tools/tts_build.py 批量合成
assets/audio/u6/single-4.m4a   ← 每拍一个文件
      ↓
index.html 里不再调 speechSynthesis，改用 <audio> 播放
字幕与动画改由 audio 的 timeupdate / ended 驱动
```

**好处**
- 音质与现在完全脱钩，不再受学生电脑装没装中文语音影响（现在这是最大的不稳定源）
- 仍然**完全离线**，和现在一样双击就能用
- 播放进度、暂停、重播、单拍重讲，都比 TTS 更可靠（TTS 的 `pause()` 各浏览器行为不一致）
- 字幕可以精确对齐（以真实音频时长为准，不再按字数估）

**代价**
- 改脚本后要重新生成音频（一条命令，实测 13 段约 40 秒）
- 仓库体积增加：**实测码率 7.13 KB/s**，按现有 3 个单元 90 拍 / 约 15.8 分钟计，**约 6.6 MB**；按每课时 30 拍外推 **约 2.2 MB/课时**

### B. 运行时调云接口

不推荐：课堂网络不可控，首字延迟、断网即失效，还要管密钥。

### C. 本地跑 CosyVoice

质量天花板最高，还能克隆固定老师的声音（教学风格统一）。
代价是每台机器要装 Python + 模型（1.4GB 内存起），且首次加载慢。
**建议作为「A 方案落地后的升级项」：仍然预生成，只是把生成端从 Edge TTS 换成 CosyVoice，对课件代码零改动。**

## 五、已经验证过的 / 还没验证的

### 已验证（可复现）

| 项 | 方法 | 结果 |
|---|---|---|
| 文件完整性 | 逐条 `afconvert` 解码 + 浏览器 `Audio` 加载 | 14 条全部可解码，时长与生成值一致（±0.1s） |
| 响度一致 | 有声帧 RMS 归一到 -19 dBFS | 除云扬被峰值上限限制在 -21.7，其余全部 -19.0±0.1 |
| 无削波 | 峰值检测 | 最高 0.95，未触及 1.0 |
| 读音正确 | faster-whisper 回读 + 与原稿比对 | 内容完整、无丢句；`2.8` 确认读作「二点八」（与汉字版时长完全一致 2.14s，「二八」为 1.94s）；`10`→「十」、`28`→「二十八」 |
| 重读确实生效 | 同文案开/关重读对比 | 21.70s → 22.68s，差值 0.98s 与两处降速幅度吻合 |

### 还没验证

1. **主观听感**——客观指标只证明「文件没坏、音量一致、字读对了」，**像不像老师讲课必须您亲耳判断**。
2. **`30` 的读法**——时长 3.00s 与「三十」(2.64s)、「三零」(2.74s) 都不吻合，回读模型也给出不一致结果，**此项未定**。安全做法：投产时把数字统一写成汉字（二点八、三十），从根上消除歧义。
3. **教室音响**——笔记本扬声器与教室扩声差异大，男声低频尤甚。
4. **多音字/专业词**——只抽查了「垂线、梯形、纵轴」，未穷举。
5. **合规**——Edge TTS 为社区方案，正式出版需换 Azure 商用接口（音色同名，切换成本极低）。
