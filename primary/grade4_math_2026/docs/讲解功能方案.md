# 「点一下就能讲」：语音 + 动画讲解功能 · 方案与三轮迭代

> 目标：老师**选中一个知识点（或某道题）→ 点「🔊 讲解」**，语音、动画、字幕三者严格同步地讲完一遍；
> 不打破课件「单文件、零外部依赖、离线可用」的硬约束。
>
> 本文档记录三轮迭代的问题与结论，并给出**已在「乘法模型二：速度 × 时间 = 路程」上跑通的 demo**。
> Demo 文件：`primary/grade4_math_2026/u4_models/demo_explain.html`（双击即开，无需联网）。

## 第 1 轮迭代：需求是否清晰

### 1.1 把一句需求拆成可判定的条目

| # | 原始表述 | 真正要回答的问题 | 结论 |
|---|---|---|---|
| 1 | 「选中某道题或者某个知识点」 | 讲解粒度有几种？ | **两种**：知识点（动画模块）、练习题；**共用一套引擎**，只是脚本来源不同 |
| 2 | 「选择讲解」 | 是「点题目就自动读」还是「点按钮才讲」？ | **显式按钮**。点题即读会在课堂上频繁误触 |
| 3 | 「增加语音和动画操作讲解」 | 语音念的是屏幕上的文字，还是另写脚本？ | **另写脚本，一份脚本同时驱动语音与动画**。照读屏幕文字必然声画不同步，也讲不出「为什么」 |
| 4 | （未提） | 讲给谁听？ | 老师放给全班 → 字幕必须**投屏可读**（≥20px） |
| 5 | （未提） | 被打断怎么办？ | 必须有 暂停 / 继续 / 停止 / 重播 / 语速 / 跳到某一拍 |
| 6 | （未提） | 离线能用吗？ | 课件硬约束 → TTS 只能用**系统语音**（Web Speech API），不调云端 |
| 7 | （未提） | 电脑没有中文语音呢？ | **优雅降级**为「字幕 + 动画按句长推进」，讲解不中断 |

### 1.2 澄清后的需求（v1，一句话版）

> 在任意知识点模块或练习题上放一个「🔊 讲解」入口；点击后按**固定六拍**推进：
> 每一拍 = 一句话（朗读）+ 一个字幕 + 一个画面状态；支持暂停/继续/停止/重播/调速/跳拍；
> 无中文语音时自动降级为「字幕 + 动画」。

### 1.3 本轮仍不确定、需要老爷拍板的点

- 是否需要**逐字高亮**（卡拉OK式字幕）？——本版没做：本地语音不返回可靠的字边界事件，
  强行做必然「字先亮、声后到」，反而破坏同步感。**建议不做**。
- 是否需要男生/女声音色切换？——本版给的是「自动挑中文女声 + 下拉可选」，够用。
- 练习题是否每道都配讲解？——建议只给 ★★★★ 以上与「易错」题配，否则备课成本压不住。

## 第 2 轮迭代：具体场景设计是否合理

### 2.1 真实课堂动线（以模型二为例）

```
① 讲完「单价 × 数量 = 总价」，进入「速度 × 时间 = 路程」
② 学生看得懂动画（小车在跑），但答不出：
     · 「60 千米/时」到底是什么单位？为什么不是「千米」？
     · 凭什么 60 乘 3 就是 180？
③ 老师点【🔊 讲解】
     → 三个量依次亮起，路程显示问号
     → 第 1 个格子填上「60 千米」，语音说「一小时走 60 千米，这就是一份」
     → 三个格子依次填满，出现「3 个 60」
     → 算式 60 × 3 = 180 落下，小车开到终点
     → 格子变绿，180 ÷ 3 = 60 回到速度
     → 三张关系式亮起，语音留下一句方法
④ 学生插问 → 老师按【⏸】，答完按【继续】
⑤ 讲完可点任一拍重听（①②③④⑤⑥ 都能单独跳）
```

### 2.2 三个备选方案

| | A 朗读屏幕文字 | B 只给现有 step 状态机配音 | **C 独立讲解脚本（话术 + 动画动作）** |
|---|---|---|---|
| 改动量 | 最小 | 小 | 中 |
| 声画同步 | ✅ | ✅ | ✅ |
| 能否讲「为什么」 | ❌ 屏幕文字是结论式 | ❌ 只有 4 步计算 | ✅ 可编排「读→问→找→算→验→迁」 |
| 能否高亮到「第 1 个格子」 | ❌ | ⚠️ 要改 render | ✅ 脚本自带 focus |
| 能否换题复用 | ❌ | ❌ 绑死模块 | ✅ 换数据即换题 |
| 课堂可用性 | 一般 | 一般 | **好**（可打断、可回放、可只讲一拍） |

**选 C**，并用两条约束防止失控：
1. 脚本只能引用课件里**真实存在**的数据（不许出现课件没有的数字）；
2. 动画只调用**已有的渲染能力**（本 demo 复用「格子 = 时间片」的画法，没有另造动画引擎）。

### 2.3 交互线框（讲解态）

```
┌──────────────────────────────────────────────────────────────┐
│ ③ 乘法模型二：速度 × 时间 = 路程                              │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │  速度 60 千米/时  ×  时间 3 小时  =  路程 ？千米           │ │ ← 三量条
│ │  ┌────────┬────────┬────────┐                            │ │
│ │  │第1小时 │第2小时 │第3小时 │  ← 时间片（每片一份）        │ │
│ │  │60 千米 │60 千米 │60 千米 │                            │ │
│ │  └────────┴────────┴────────┘                            │ │
│ │  ●━━━━━━━━┿━━━━━━━━┿━━━━━━━━▶🚗  0 / 60 / 120 / 180 千米  │ │
│ │            3 个 60 千米　路程 = 速度 × 时间                │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌ 🔊 列式算 ───────────────────────────────────────────────┐ │ ← 字幕条
│ │ 60 × 3 = 180（千米）· 单位：千米/时 × 时 = 千米            │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [🔊开始讲解][⏸暂停][⏹停止][↻重播] 语速●─○ [中文女声▾]      │
│ ①读信息 ②提问 ③找关系 ④列式算 ⑤检验 ⑥迁移   ← 可点跳拍      │
└──────────────────────────────────────────────────────────────┘
```

### 2.4 本轮做出的三个设计决定

1. **入口不抢原有习惯**：讲解按钮与「一步步算」并列，原有手动步进保留；讲解时锁手动步进，
   停止后恢复（本 demo 未内置「一步步算」，接入正式课件时按此处理）。
2. **字幕在舞台正下方**：视线顺序 =「看动画 → 看字幕 → 看节拍」，符合讲解节奏；
   字幕条固定高度，避免每句话长短不同导致页面抖动。
3. **节拍可点**：老师经常只需要重讲第 ③ 拍（找关系），不重播整段。这是课堂高频动作，必须支持。

## 第 3 轮迭代：通俗易懂 + 数学思维培养

### 3.1 先说结论：不能把算式读一遍

流水账讲法：「60 乘 3 等于 180，所以是 180 千米」——学生记住了**计算结果**，没学到**思考方式**。
数学思维的落点在**建模过程**：

```
读信息 → 提出问题 → 找关系（建模） → 列式计算 → 检验 → 迁移
```

六拍骨架固定，每一拍都要有「话术 + 画面」：

| 拍 | 目标 | 话术要点（模型二） | 画面动作 |
|---|---|---|---|
| ① 读信息 | 不急着算 | 「先别急着算，看清楚已知什么、问什么」 | 三量条亮起，路程显示「？」 |
| ② 提问 | 制造认知冲突 | 「60 千米/时 是什么意思？为什么单位里有个『每』？」 | 只填第 1 个格子，标「1 份」 |
| ③ 找关系 | **思维核心** | 「1 小时 60，2 小时 2 个 60，3 小时 3 个 60 → 求几个几，用乘法」 | 三个格子依次填满，出「3 个 60」 |
| ④ 列式算 | 规范表达 | 「60 乘 3 等于 180，单位是千米」＋单位配对说明 | 算式落下，小车开到终点 |
| ⑤ 检验 | **高光时刻** | 「180 除以 3 回到 60，和原来的速度对上了」 | 格子与公路变绿，出检验式 |
| ⑥ 迁移 | 留下方法 | 「先找每份是多少，再看有几份；每千克、每分钟都是这个模型」 | 三张关系式亮起 |

> ⑤ 和 ⑥ 最容易被省，也最能体现思维：前者教「回头看」，后者教「下次怎么办」。

### 3.2 模型二特有的三个「坑」，必须在讲解里正面处理

| 坑 | 学生的真实困惑 | 讲解怎么破 | 对应拍 |
|---|---|---|---|
| 复合单位 | 「千米/时」不像个单位 | 把它翻译成「每 1 小时行多少千米」，斜杠读作「每」 | ② |
| 速度 ≠ 路程 | 把 60 当成「走了 60 千米」 | 只填第一个格子，明确「这是一份，不是总数」 | ②③ |
| 模型同构 | 学完就忘，换个情境不会 | 迁移拍点明「每千克多少元、每分钟多少米，都是每份 × 份数」 | ⑥ |

### 3.3 通俗易懂的四个手法

1. **生活锚点**：不说「速度是位移对时间的变化率」，说「一小时走多远」。
2. **听说同指**：语音说「第 1 个格子」时，画面上正是那个格子亮起——耳朵和眼睛指向同一处。
3. **一句一事**：每句 ≤ 30 字，一句只推进一步。
4. **数字读顺**：字幕写 `60 × 3 = 180`，朗读文本写成「60 乘 3 等于 180」——符号不进 TTS。

### 3.4 可验收的「思维培养」落点

| 落点 | 验收方式 | demo 实测 |
|---|---|---|
| 有提问 | 脚本里至少 1 句问句 | ✅ 第 ② 拍两个问句 |
| 有关系式 | 出现「×」关系式且与课件要点一致 | ✅ ③④ 拍 |
| 有检验 | 出现「÷ 回到速度」且画面上有对应变化 | ✅ ⑤ 拍，格子转绿 |
| 有迁移 | 末拍含「每…都是这个模型」的方法总结 | ✅ ⑥ 拍 |
| 不剧透 | ①②③ 拍不出现答案 180 | ✅ 实测：答案首次出现在第 ④ 拍 |

## 四、技术方案（零外部依赖）

### 4.1 语音：Web Speech API

- `speechSynthesis.speak()`，自动挑 `zh-CN` 女声（Ting-Ting / 晓晓 / 美佳 优先），可下拉切换；
- 每条话术单独一句 `SpeechSynthesisUtterance`，`onend` 驱动进入下一拍；
- **兜底计时**：`onend` 不触发时（部分系统语音的已知问题）按「字数 × 235ms ÷ 语速」估算的 2 倍超时强制推进，避免卡死；
- **降级**：`getVoices()` 为空 → 不使用语音，改按句长计时推进字幕与动画。

### 4.2 动画：绝对状态，而不是增量

每一拍的 `act()` 把画面**设置成该拍的完整状态**（不是「再往前一步」）。
好处：任意跳拍、暂停后继续、反复重播都不会出现状态错乱；这是本方案能支持「点节拍重听」的前提。

### 4.3 引擎 API（业务侧只写脚本）

```js
Narrator.mount(hostEl, {
  beats: ['读信息','提问','找关系','列式算','检验','迁移'],
  steps: [
    { beat:'读信息', say:'朗读文本…', sub:'字幕<b>HTML</b>…', act(){ /* 画面设成该拍状态 */ } },
    …
  ],
  onStep(i, st){ st.act(); }      // 引擎在每拍开始时调用
});
```

引擎负责：语音、字幕、节拍高亮、暂停/继续/停止/重播/语速/跳拍、快捷键（空格暂停、Esc 停止）、
「同一时刻只允许一个讲解在播」（切换面板自动停另一个）。

### 4.4 练习题讲解（同一引擎，零额外成本）

题目脚本 = 同一六拍骨架，`act()` 换成「展开该题的步骤面板 / 高亮线段图的某几格」。
demo 里的第二块就是这么做的：**5 小时 300 千米，照这样计算，2 小时行多少千米**（归一问题），
线段图 5 格 → 高亮前 2 格。

## 五、Demo 实测结果

环境：macOS + Chrome（Playwright 驱动），文件以 `file://` 打开，断网可用。

| 检查项 | 结果 |
|---|---|
| 页面加载 console error / pageerror | **0 条** |
| 首屏待机态文案、6 个节拍、题目 5 格、SVG 已绘制 | 自检 `__demoCheck()` **全部通过** |
| 有语音路径：播放 → 跳到第 ④ 拍 → 停止 | 状态 `playing → idle`，字幕与算式正确切换 |
| 无语音路径（强制移除 `speechSynthesis`）：整段跑完 6 拍 | 81 秒走完 ①→⑥，终态 `done`，无报错（语速 1.3×） |
| 括号与格子对齐 | 实测 `.bseg` 右边界 570px = 第 2 格右边界 570px，误差 0 |
| 数值正确性 | 60×3=180、40×5=200、300×2=600、300÷5=60、60×2=120、120÷2=60 |

**未验证 / 需老爷人工确认的部分**（不编造结论）：

- 真实音箱下中文语音的音色与断句是否自然——需要人耳判断，自动化测不了；
- 投屏（1024×768 以上）在教室后排的可读性——建议实际投一次；
- Safari / Firefox 的 `speechSynthesis.pause()` 行为差异——本 demo 只在 Chrome 上验证过。

## 八、三轮评审成为固定关卡（2026-10-31，纳入 skill v1.1）

**问题**：v1.0 的 skill 只写了"怎么执行"（六拍骨架、控制器、构建、自检），
没写"动手之前怎么想"。结果是脚本能跑通，但教学目标、课堂场景、讲法是靠临时判断定的，换个单元就重来一遍。

**补齐**：skill 新增第三节「三轮方案评审（写代码前的必过关卡）」+ `references/iterations.md`，
生产流程改为「第 0 步 三轮评审 → 第 1 步 盘课型 → … → 第 5 步 交付」，
硬规则加第 11 条（无 `iterations.md` 或无推翻记录不得写 `narr.js`）。
记录落到每个单元的 `iterations.md`，与脚本一起交付。

三轮各问一件事，且必须有"被推翻"的一处：

| 轮次 | 问题 | 通过判据 |
|---|---|---|
| 一 | 需求是否清晰 | 主场景 / 范围 / 时长 / **一句话目标（可测行为）** / 数据核查 |

## 十、语音自然度：从「念稿」到「像老师讲」（第六单元试点）

上一节留的"尚未验证"里，第一条就是断句与连读。本轮把它解决了，方法不是换引擎，而是三件事叠加。

| 杠杆 | 做法 | 实测效果 |
|---|---|---|
| ① 文案口语化 | 24 拍 `say` 全改写：加「你看 / 咱们 / 你注意」、真设问、短句拆分（平均 28 字/拍） | 收益最大，且不花钱 |
| ② 断句留白 + 重读 | 逗号 300ms / 顿号 280ms / 句号 620ms；`emp` 片段降速 26% | 一拍从"一口气念完"变成有换气 |
| ③ 预生成神经语音 | 晓晓音色，64kbps，base64 内联进 `index.html` | 与「学生电脑装没装中文语音」彻底脱钩 |

**关键结论：换引擎只解决「音色好不好听」，①② 不解决就还是「清晰的机器音」。顺序不能反。**

### 踩到并修掉的三处

1. **数字列举被念成一串**：`28、22、18、12、6` 读成「282218126」。顿号必须切段并留 280ms；
   验证靠能量包络数停顿（`5、7、2、6、2` 修复后有 4 个 370~400ms 停顿），不能靠转录文本。
2. **分段合成导致一拍凭空多 3~5 秒**：每段首尾自带静音，拼接会累积。裁掉后总时长 296.6s → 205.5s。
3. **括号读音**：`say` 里「四（1）班」会念成「四括号一班」，改写成「四一班」，`sub` 保留括号。

### 数据

| 项 | 值 |
|---|---|
| 音色 | 晓晓 `zh-CN-XiaoxiaoNeural`，rate -10% |
| 音频 | 24 条 / 207 秒 / 1682KB / 64kbps 单声道 AAC |
| 产物 | `index.html` 单文件 2.3MB，双击即用（音频 base64 内联） |
| 回读校验 | 24 条数字全部读对：`2.8`→二点八、`28`→二十八、`30`→三十、`103`→一百零三 |

### 推广时踩到的四类问题（都不是语音本身的问题）

**① 画面不推进：只改颜色，不进 DOM。**
`u7_review` 的知识地图、`u6_average` 的旅游计划、`u5_decimal_add` 的对齐模块，
初版都只在样式上做高亮，`check_explain.py` 一跑就是「1 个不同画面」。
定下硬规则：**每拍必须有实体文字或图形进出 DOM**，纯样式变化不算推进。
补法一律是"在图上叠加真标注 ＋ 下方加一行随拍更换的说明条"。

**② 控制器挂错作用域。**
`u5_decimal_add` 的 `MOD.align` 被写进了 `initAdd`，`#s-align` 根本拿不到控制器，
表现为"点什么都没反应"。教训：控制器必须紧跟它自己的 `initXxx` 收尾处定义。

**③ 状态数不够撑 6 拍。**
四步的模块走六拍，必然有两拍撞画面。三种补法：
扩步数（`u6_average` 比较模块 4 步 → 5 步；`u7_review` 综合应用 4 步 → 6 步）、
加对照组（`u3_triangle` 加"四边形一推就歪"）、
加结论条（`u7_review` 知识地图分层展开 1→7 张卡）。

**④ 步进器与控制器不同步（真 bug，不是自检误报）。**
`u6_average` 的方案下拉框 `change` 只重置了 `step`，没把选项值同步给内部状态 `ci`，
选方案 B 画面纹丝不动；`u7_review` 的 `MOD.apply` 不接收人数，
讲解说 30 人、滑块可能停在 50 人。都已修：**控制器与 UI 控件必须双向同名同值**。

### 闸③ 的回读修正：同音字不是读错，但可以规避

推广到 14 个单元后，回读校验一共报出 5 条存疑，全部属于"方言级同音混淆"，逐条规避：

| 单元 | 原句 | 回读成 | 改法 |
|---|---|---|---|
| u7_review | 四一班 30 人去春游 | 四一般**三世人** | 加量词：「30 **个人**」 |
| u1_divide | …商 8。 | …**伤势**八 | 补上下文：「8 乘 30 正好 240，商是 8」 |
| u4_decimal | 不满 1 了 | 不满**一**了（吞字） | 补名词：「不满 1 **个整的**」 |
| u5_decimal_add | 百分位上的 8 | 百分位上的**吧** | 换语境：「3.68 **里的** 8 在百分位上」 |
| u5_decimal_add | 5 的后面… | **我的**后面 | 补限定：「**整数** 5 后面…」 |

**规律**：孤立数字落在句尾或紧跟"的"时最容易被吞。规避手段只有三种——
加量词（个／辆／人）、补上下文让它和相邻数字连读、把数字挪到句中。
这比调语速有效得多，也不影响听感。
