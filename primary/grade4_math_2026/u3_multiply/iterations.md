# u3 三位数乘两位数 · 讲解方案三轮评审

> 依据 `math-courseware-explainer` skill：每节讲解必须过三轮评审
> （① 需求是否清晰 ② 场景设计是否合理 ③ 通俗易懂且体现数学思维培养），
> 每轮至少推翻一处原设计。

本单元 5 节 × 6 拍 = 30 拍。

---

## 一、口算乘法（#s-oral）

**一轮｜需求**
初稿把「20×30」当成技巧题讲「先算 2×3 再添 0」。
→ 推翻：技巧背后是**计数单位**。需求改成「让孩子看清 20×30 是 6 个百」，
而不是「记住添几个 0」。

**二轮｜场景**
原动画只高亮两个 0。
→ 推翻：0 是结果不是原因。改为把 `20` 拆成「2 个十」、`30` 拆成「3 个十」两块牌子，
两块牌子相乘时把「十 × 十 = 百」这层关系显式画出来，
孩子看到的是「单位在变」，不是「0 在长」。

**三轮｜通俗 + 思维**
「末尾添两个 0」被当成规则。
→ 推翻：迁移拍补 `300×40`，先问「添几个 0」再问「为什么是三个」，
把规则还原成「两个因数末尾 0 的个数相加」——这是**单位换算的加法性**，可迁移到小数乘法。

---

## 二、笔算乘法（#s-vertical）

**一轮｜需求**
初稿按教材顺序讲「先用个位乘，再用十位乘，最后相加」。
→ 推翻：顺序是操作，不是理由。需求应先回答「为什么要写两行」。

**二轮｜场景**
原动画一次把两行都写出来。
→ 推翻：必须**分两拍**呈现，第二行出现时同步显示「145 个十」的说明，
并让第二行末尾那个 0 用虚线占位——把「补 0」变成看得见的位置。

**三轮｜通俗 + 思维**
「第二行忘补 0」是最常见错误，原稿只提醒。
→ 推翻：改成**用位值解释错误后果**：「不补 0 就等于把 145 个十当成了 145 个一，
答案小十倍」。让孩子知道错的不是格式，是数的大小。

---

## 三、因数中间或末尾有 0（#s-zero）

**一轮｜需求**
初稿把「末尾有 0」和「中间有 0」混在一节讲。
→ 推翻：两者性质完全不同——末尾 0 可暂存，中间 0 占位必须算。拆成「先讲可暂存，再打反例」。

**二轮｜场景**
原动画只演示 `25×40`。
→ 推翻：五拍讲完 `25×40` 后画面已无变化，第六拍会撞画面。
改为第六拍切到 `307×25`，把中间 0 单独框出来标「占位，不能丢」，
形成「可省 / 不可省」的对照画面。

**三轮｜通俗 + 思维**
原稿说「中间 0 不能丢」是命令。
→ 推翻：给理由——「307 里的 0 站在十位上，它一丢，3 就从百位掉到十位」。
把「不能丢」变成「丢了数位就错位」，这是位值制的核心。

## 四、积的变化规律（#s-law）

**一轮｜需求**
初稿列举「一个因数不变，另一个乘几，积就乘几」。
→ 推翻：规律要**从数据里长出来**，不能先给结论。需求改成「先算一组，再发现」。

**二轮｜场景**
原动画只换数字，表格不累积。
→ 推翻：改为逐行往表格里追加（12×5=60 → 12×10=120 → 12×20=240），
每追加一行就把「×2」的箭头画在因数上、「×2」的箭头画在积上，
两条箭头成对出现，规律自然显形。

**三轮｜通俗 + 思维**
只讲「乘」，不讲「除」，也不讲用途。
→ 推翻：迁移拍补反向（15 是 5 的 3 倍 → 积 180）并点明用途
「算面积、算总价用的都是这一条」，让规律从题目里走到生活里——
这是**函数思想的第一次露面**（一个量变，另一个量按比例变）。

## 五、估算与解决问题（#s-estimate）

**一轮｜需求**
初稿把估算讲成「四舍五入再相乘」。
→ 推翻：估算的目的是**判断够不够**，不是求近似值。需求改成「用估算做决策」。

**二轮｜场景**
原动画只显示估算结果 6000，然后直接说「够」。
→ 推翻：这是**逻辑漏洞**——两个因数都估小了，6000 只是下界。
改为第二段显示精确值 6342 与 7000 的差距条，用「下界 + 精确值」双证据下结论。

**三轮｜通俗 + 思维**
估算被当成「不准的算法」。
→ 推翻：迁移拍用 `198×52` 做**反例**：估成 200×50 = 10000 正好卡在线上，
凭估算无法判断，必须精确算 10296 才知道不够。
让孩子明白：估算能快速排除，但**卡在边界时必须回到精确计算**——
这是「估算与精确计算互补」的判断力，比会算更重要。
