# u2 混合运算和运算律 · 讲解方案三轮评审

> 依据 `math-courseware-explainer` skill 的强制流程：每节讲解脚本必须经过三轮评审
> （① 需求是否清晰 ② 场景设计是否合理 ③ 通俗易懂且体现数学思维培养），
> 每轮必须**至少推翻一处**原设计，推翻结论落到代码。

本单元 5 节 × 6 拍 = 30 拍。以下按节记录三轮评审中被推翻的地方。

---

## 一、混合运算的顺序（#s-order）

**第一轮｜需求是否清晰**
初稿把「同级运算、两级运算、带括号」三种情形当成三拍并列。
→ 推翻：三种情形是**同一条优先级规则的三次应用**。
主线改为「先扫一遍有没有括号 → 再找乘除 → 最后加减」，把规则变成"看一遍的顺序"。

**第二轮｜场景设计是否合理**
原设计是静态列出算式和答案，六拍里五拍画面一样。
→ 推翻：必须在算式上**标出"下一步算哪一块"**——用红框逐步圈出要算的部分，
圈的位置逐拍移动，孩子看到的是"眼睛该往哪看"。

**第三轮｜通俗易懂 + 数学思维**
「先乘除后加减」是记下来的。
→ 推翻：要给**反例**——若先算 24+6，结果 150 而不是 54，
在生活情境里意味着"多买了 4 倍的东西"。让规则产生后果感。

---

## 二、加法的交换律与结合律（#s-addlaw）

**第一轮｜需求是否清晰**
初稿把两条定律分开讲，各举一例。
→ 推翻：两条定律要合成一个动作——「找能凑整的两个数」。
主线改为「凑十 → 凑百 → 交换/结合只是工具」。

**第二轮｜场景设计是否合理**
原设计用字母 a、b、c 表达，四年级孩子对字母不敏感。
→ 推翻：**具体数先行**。画面里先出现 38+72+28，让孩子看到 72+28=100 的瞬间，
再把字母写在旁边作"缩写"，而不是反过来。

**第三轮｜通俗易懂 + 数学思维**
只讲"可以换位置"。
→ 推翻：要讲清**为什么可以换**——加法是把东西合在一起，先合哪两堆不影响总数。
迁移拍换成"一堆苹果一堆梨"的图示，把定律还原成"合并"这件事。

---

## 三、乘法的交换律与结合律（#s-mullaw）

**第一轮｜需求是否清晰**
初稿把乘法的两条定律和加法并列，用同一套讲法。
→ 推翻：乘法结合律的用处远大于交换律（125×32×25 这类题全靠它）。
主线改为「先看有没有 125、25 这种"好搭档" → 再拆数去凑」。

**第二轮｜场景设计是否合理**
原设计一次性把两组算式都摆出来。
→ 推翻：`M.mullaw.set(A, B, lvl)` 改为**三级揭示**：
lvl 0 只给第一组，lvl 1 长出第二组，lvl 2 才出结论框。
每一级画面都换，六拍不撞。

**第三轮｜通俗易懂 + 数学思维**
「125×8=1000」被当成要背的特殊数。
→ 推翻：要讲清它是**凑整的结果**——125 是 1000 的八分之一，
所以见到 125 就找 8。把"背搭档"升级成"看谁是谁的几分之一"。

---

## 四、乘法分配律（#s-distrib）

**第一轮｜需求是否清晰**
初稿只讲正用 (A+B)×C = A×C + B×C。
→ 推翻：分配律真正的难点在**逆用**（A×C + B×C = (A+B)×C），
而逆用的动机是"凑整"。主线改为「先面积模型看懂 → 再逆用去凑整」。

**第二轮｜场景设计是否合理**
（本轮为自检后二次修正）
① 面积模型原来用字母 A、B、C，抽象得看不出"两块拼成一整块"。
→ 推翻：改成具体数 `const C = 25;`，右侧算式写死 `(A + B) × C = A×C + B×C`，
并在下方标「整块 = (A+B)×C」。
② 检验拍与迁移拍都调 `M.distrib2`，画面完全重复，闸①判「与前一拍同画面」。
→ 推翻：检验必须**换一种分法**——改为 `M.distrib.set(30, 3)`（把 30 拆成 20+10），
迁移再 `M.distrib.set(60, 3) + M.distrib2.set(6)`。
修正后画面推进 6 个，闸①全绿。

**第三轮｜通俗易懂 + 数学思维**
「拆成两个数相乘」容易变成乱拆。
→ 推翻：要给**拆的依据**——「拆出来的数要和另一个因数凑整」。
迁移拍用 88×125 演示：拆成 8×11 而不是 80+8，因为 125 要的是 8。

## 五、简便计算（#s-simple）

**第一轮｜需求是否清晰**
初稿把简便计算讲成"技巧集合"。
→ 推翻：技巧没有共同标准。主线改为「先看数有什么特点 → 再选定律 →
最后验算结果是否和原式一致」，把技巧收成**三步流程**。

**第二轮｜场景设计是否合理**
原设计每拍换一道题，孩子只看到题在换，看不到"为什么选这条定律"。
→ 推翻：画面必须**先标出数的特点**（如 25 与 4、125 与 8 用同色连起来），
再出现定律名。顺序反过来就变成"猜"。

**第三轮｜通俗易懂 + 数学思维**
没有检验环节，简便计算算错也不自知。
→ 推翻：检验拍固定加一句「用原式再算一遍，和简便结果对一对」，
把"简便"和"可靠"绑在一起，避免为快而错。
