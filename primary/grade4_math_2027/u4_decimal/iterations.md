# u4 小数的认识 · 讲解方案三轮评审

> 依据 `math-courseware-explainer` skill 的强制流程：每节讲解脚本必须经过三轮评审
> （① 需求是否清晰 ② 场景设计是否合理 ③ 通俗易懂且体现数学思维培养），
> 每轮必须**至少推翻一处**原设计，推翻结论落到代码。

本单元 5 节 × 6 拍 = 30 拍。以下按节记录三轮评审中被推翻的地方。

---

## 一、小数的意义（#s-meaning）

**第一轮｜需求是否清晰**
初稿把「小数的产生、小数的读法、小数的组成」三块并列。
→ 推翻：意义只讲一件事——**把 1 平均分成 10 份、100 份之后的那一份怎么记**。
主线改为「分 1 元 → 记成 0.1 → 再分 → 记成 0.01 → 归纳」。

**第二轮｜场景设计是否合理**
原设计只有文字描述"分成十份"，没有可数的东西。
→ 推翻：必须用**可数的实物**（1 元分成 10 角、1 米分成 100 厘米），
并在图上画出分格与涂色，每拍涂色块数变化，画面才推进。

**第三轮｜通俗易懂 + 数学思维**
只讲"十进制"，不讲**为什么是十**。
→ 推翻：迁移拍补一句"因为满十进一，所以往下分也按十份分"，
把孩子已经有的"十进制"经验接到小数上，小数就不是新东西，而是同一个规则的延续。

---

## 二、数位顺序表（#s-place）

**第一轮｜需求是否清晰**
初稿直接给数位顺序表。
→ 推翻：表是结论，不是起点。主线改为「先给一个数 →
问每个数字表示多少 → 排出位置 → 才成表」。

**第二轮｜场景设计是否合理**
原设计六拍里五拍都是同一张表，只是高亮不同格子。
→ 推翻：`M.place` 每拍必须**在新位置长出一段说明文字**（`PCAP[step]`），
如"3 在百分位，表示 3 个 0.01"。高亮不算推进，文字进 DOM 才算。

**第三轮｜通俗易懂 + 数学思维**
「数位与计数单位一一对应」偏术语。
→ 推翻：改成孩子能说的句子——"第几位，就代表把 1 分成几份"，
并用 0.305 这种带 0 的例子检验（0 也占位），把"占位"讲透。

---

## 三、小数的读法和写法（#s-read）

**第一轮｜需求是否清晰**
初稿把读、写分成两节内容一起讲。
→ 推翻：读写是同一件事的两个方向，难点都在**中间有 0**。
主线改为「整数部分按整数读 → 小数部分逐位读 → 中间的 0 一个不能丢」。

**第二轮｜场景设计是否合理**
原设计的例子都是没有 0 的"顺"数字。
→ 推翻：必须用 0 多的数（20.005、0.030）当主例，
并在读法上逐位对齐标注，让"读错在哪"看得见。

**第三轮｜通俗易懂 + 数学思维**
「小数部分按顺序读数字」被当成规定。
→ 推翻：要讲清**为什么不能按整数的读法读**——0.35 不是"零点三十五"，
因为十分位和百分位不是一个"级"。把规则变成"避免歧义"的必要手段。

---

## 四、小数的性质（#s-property）

**第一轮｜需求是否清晰**
初稿把"添 0、去 0、化简、改写"四件事并列。
→ 推翻：四件事是**同一个性质的正反两个方向**。
主线改为「末尾添 0 大小不变 → 末尾去 0 大小不变 → 用于化简与改写」。

**第二轮｜场景设计是否合理**
原设计只在数字上添 0，看不出"大小不变"。
→ 推翻：必须同时给出**两种表示**（0.3 元 = 0.30 元 = 3 角），
并在下方固定一行说明（`QCAP[step]`）随拍更换，否则六拍文字一致。

**第三轮｜通俗易懂 + 数学思维**
「只有末尾的 0」这个限定常被漏掉。
→ 推翻：检验拍必须给**反例**——0.405 中间的 0 去掉就变成 0.45，
数变大了十倍。让"末尾"这个限制由反例守住，而不是靠加粗。

---

## 五、小数的大小比较（#s-compare）

**第一轮｜需求是否清晰**
初稿把比较讲成"从高位比起"一句口诀。
→ 推翻：口诀解决不了"位数不同"的困惑（0.9 和 0.89 谁大）。
主线改为「先看整数部分 → 再看十分位 → 位上大的就大 → 位数多不代表大」。

**第二轮｜场景设计是否合理**
（本轮为自检后修正）
提问拍的 emp 写的是「变大了十倍」，但 say 里说的是「一下大了十倍」，
逐字不匹配，闸①报「emp 不在 say 里」。
→ 推翻：emp 必须逐字取自 say。改为 `'大了十倍'`（是 say 的子串）。
同时比较过程改为**逐位对齐竖排**（`CCAP[step]` ＋ `rel` 计算），
每拍在下方写一句判断依据。

**第三轮｜通俗易懂 + 数学思维**
「位数多的不一定大」只当提醒说一句。
→ 推翻：要用 0.9 与 0.89 这组对照反复出现，
让孩子自己发现"补 0 之后位数一样了，就能按位比"——把困惑变成方法。

## 汇总：本轮共推翻 14 处

| 数位顺序表 | 直接给表 → 从数倒推表 | 高亮格子 → PCAP 说明进 DOM | 术语 → "第几位就是分成几份" |
| 读法和写法 | 读写分开 → 难点都在 0 | 顺数字 → 用 0.030 主例 | 规定 → 避免歧义的必要 |
