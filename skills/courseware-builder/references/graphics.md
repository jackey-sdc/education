# 绘图正确性手册（SVG / Canvas 通用）

图形类课件最容易出的不是"画不出来"，而是**画出来是错的**——而肉眼看很难发现。
本手册给出统一的坐标约定、常见陷阱清单与**可自动验证**的方法。

---

## 一、坐标与角度约定（先定死，再画任何东西）

统一约定，可直接抄进模板：

```js
// 角度以「数学正方向 = 逆时针」为正；SVG/Canvas 的 y 轴向下，所以 y 取负
function polar(cx, cy, r, deg){
  const a = deg*Math.PI/180;
  return [cx + r*Math.cos(a), cy - r*Math.sin(a)];
}
```

派生约定：
- 屏幕上"顺时针"= 数学负方向；凡是"转过多少度"的教学表述，先确认是哪个方向。
- 需要屏幕顺时针时传入负角度，或用 `polar(cx, cy, r, -deg)`，不要改 helper 语义。
- 图形一律用 SVG（清晰、可选中、可被断言）；需要大量粒子/像素级绘制才用 Canvas。

## 二、弧线方向：最典型也最隐蔽的坑

**SVG 的 `sweep-flag=1` 表示屏幕顺时针**，而教材里的角通常按数学逆时针定义。
标志用反时，弧线会绕远路跑到图形外面，肉眼容易放过。

**统一 helper，禁止各处手写 `A` 命令**：

```js
function arcPoints(cx, cy, r, startDeg, spanDeg){
  const p1 = polar(cx,cy,r,startDeg), p2 = polar(cx,cy,r,startDeg+spanDeg);
  const large = spanDeg > 180 ? 1 : 0;
  return { p1, p2, m:`M ${p1[0]} ${p1[1]}`,
           d:`A ${r} ${r} 0 ${large} 0 ${p2[0]} ${p2[1]}` };  // sweep 固定 0
}
```

配套规则：
- 起止角必须满足 `end = start + span`（`span` 为正）。
- "起点在右、终点在左"的角度（如钝角跨过垂直方向），要**改起点**成 `180-θ`、终点 `180`，
  不要靠 sweep 标志去凑方向。
- 起终点重合（0°→360°）时 SVG **不画弧**，特判成 `<circle>`。

## 三、出框与裁剪

- 画之前算端点：射线的端点 = `polar(vertex, len, deg)`，检查 x/y 是否落在 viewBox 内。
  大角度（>90°）时 x 很容易变负；必要时把顶点右移或缩短射线。
- 标注跟随端点时，用**极坐标**算位置（跟随机旋转无关），不要手写 x/y 偏移。
- 给 SVG 加 `viewBox` + `width/height`，容器用 `max-width:100%;height:auto` 保持等比缩放；
  绝不用非等比的 `preserveAspectRatio="none"` 拉伸图形。

## 四、文字重叠与遮挡

| 手段 | 适用 |
|---|---|
| 沿切向旋转排版 `rotate(deg-90 x y)` + `dominant-baseline="central"` | 圆周上的刻度数字、序号 |
| 白色描边光晕 `paint-order:stroke` + `stroke:#fff` + `stroke-width:3.5` | 被射线/指针/曲线压住的文字 |
| 标注放在图形**外侧** + 引线指向对象 | 结构图、部件说明 |
| 字号分级（主数值大、刻度小、注释更小） | 同屏信息层级 |

## 五、其他高频图形陷阱

- **`<line>` 的坐标对**：`x1,y1,x2,y2`。把 `y2` 误写成 `y1` 会让刻度线拉成长条横杠——极常见。
- **`path` 闭合**：填充区域要 `Z` 闭合；只描边不填充时 `fill:"none"`。
- **点击热区**：细线/小点难以点击时，叠加一层透明（`fill:"transparent"`）的粗 `line`/`circle` 承接事件。
- **箭头**：用 `<marker>` 定义，统一方向与大小，避免每次手画。
- **颜色语义**：同一概念在全课用同一颜色（角弧=橙、边=蓝/绿、顶点=深灰），写进变量或常量。
- **动画只改参数**：播放动画与手动拖拽共用同一个渲染函数，状态只有一份。

## 五之二、数位对齐类图形（竖式 / 数位表 / 统计表）

这类图形的数字**位置对了不等于写法对了**——自动断言只能验"列与列自洽"，
验不了"是否与教材一致"，必须对照教材核一次。

### 1. 竖式的部分积要写成"左移后的完整积"

人教版笔算乘法的竖式，十位上的数乘得的积**末尾补 0**，写成完整积：

```
    1 4 5        第一个因数 145
  ×   1 2        第二个因数 12（个位与 145 个位对齐）
  -------
    2 9 0        ← 145 × 2
  1 4 5 0        ← 145 × 1 × 10 = 1450（末尾的 0 是补位）
  -------
  1 7 4 0        ← 290 + 1450 = 1740（每一列都对得上）
```

如果把十位的部分积写成"145"再左移，竖式里就变成 `290 + 145 ≠ 1740`，
学生会照着图读出一个错误经验。

**通用做法**：第 i 行的部分积一律取 `a × B[i] × 10^i` 的**完整值右对齐**，
而不是"把 a×B[i] 的数字整体挪 i 格"。这样每一行天然就是加法里的一项。

### 2. 占位 0 什么时候出现

左移产生的那个 0 是**算完这一行后**才补上的：
计算过程中该格留空（写着算得更快），整行算完再补 0，视觉上才成立。

### 3. 位名按"实际所在列"算

部分积左移 i 位后，被乘数第 j 位上的数字落在**第 j + i 列**。
讲解文字里的"在个位写/在十位写"必须用这个列号，不能用 j。

### 4. 逐步演示不能提前给答案

未算出的格子一律留空：按"已完成的步骤数"决定每格填不填。
预填最终结果再移动高亮，等于假动画——学生会以为竖式是天上掉下来的。

### 5. 断言怎么写

把每一行的数字按列读出来（读格子文本 + 列号），然后**用算式反查**：

```js
// 竖式自检：各部分积之和 == 结果行；部分积必须是左移后的完整积
const rows = readRowsByColumn();          // [[…列0], […列1], …]
const parts = rows.filter(r => r.isPartial);
const sum = parts.reduce((a, r) => a + Number(r.digits), 0);
const res  = Number(rows.find(r => r.isResult).digits);
return sum === res;                        // 还要单独断言：第 0 步没有出现这些数字
```

再加一条"第 0 步不得出现 290/1450/1740"，防止答案被预填。

## 六、验证方法（核心）

### 几何断言：量坐标，不靠看

用 `getPointAtLength()` 取**实际渲染路径**的中点，再换算成极角，验证它落在期望方向上：

```js
const p = [...svg.querySelectorAll('path')]
  .filter(x => (x.getAttribute('stroke')||'') === '#f08a24').pop();
const pt = p.getPointAtLength(p.getTotalLength()/2);
const ang = Math.atan2(-(pt.y-cy), pt.x-cx) * 180/Math.PI;   // 记得翻 y
// 断言 ang ≈ 期望值
```

可断言的几何量（不限于弧线）：

| 量 | 方法 |
|---|---|
| 方向/角度 | 路径中点极角 vs 期望角 |
| 长度/比例 | 两点距离之比 vs 期望比例 |
| 对齐/同心 | 圆心坐标、半径差 |
| 端点位置 | `getBBox()` / 元素坐标 vs 期望 |
| 元素数量 | `querySelectorAll(...).length` vs 期望（数格子、数线段、数角） |
| 出框 | `getBBox()` 是否越出 viewBox |

### Canvas 的对应做法

Canvas 没有可查询的 DOM 元素，无法直接断言渲染结果。两条路：
1. 把几何量算在**模型层**（即"我打算画什么"），对模型断言，而不是对画布断言；
2. 用 `ctx.getImageData()` 取像素做存在性/颜色检查（较慢，适合少量关键点）。

**建议**：能用 SVG 就用 SVG，断言成本低一个数量级。

### 截图复核（补自动断言的盲区）

自动断言管"对不对"，截图管"好不好看"。每个 section 截一张图，人工过一遍：
排版错位、文字压线、留白失衡、深浅色对比。

## 七、交付前最后一眼

- 动画里出现的每个数值/结论，都要有对应的可断言依据（"转过 90°"→ 断言指针角度差 = 90）。
- 图形与文字描述一致性：图上标 45°，文案别写 40°。
