# 答案正确性校验手册

> 主题：**怎么证明"答案和解析是对的"，而不是"引擎说它是对的"。**
> 适用：任何带选择题/填空题的互动课件。

---

## 〇、为什么需要这一层

引擎判定"答对"用的是题目数据里声明的答案（`a:0` / `a:'17'`）。
**引擎与题目数据同源**——两者一起错时，任何"回填答案看引擎是否判对"的自洽性测试**照样全绿**。

```
题目数据写错 a:1  →  引擎忠实地把第 2 个选项判为"正确"  →  自洽性测试通过 ✅（但内容是错的）
```

所以校验要分四层，**层层独立**：

| 层 | 问题 | 谁来答 |
|---|---|---|
| L1 自洽 | 引擎认不认自己声明的答案 | `test_answers.py` |
| L2 **独立复算** | 答案**本身**对不对（不看引擎，自己算） | `check_answers.py` |
| L3 **答案×解析交叉** | 答案与解析有没有打架 | `check_answers.py` |
| L4 **语义/建模** | 题干前提、条件、单位、图形关系、选项唯一性是否成立 | `check_answers.py` + 人工复核 |

L2/L3/L4 的细则见下文。**只做 L1 等于没做。**

## 一、L2：独立复算（能机械算的题）

### 1.1 从题干抽算式

规则（`extract_expr`）：

- 题干必须以 `是（　）` 收尾（问结果）
- 取 `是（　）` 之前**最靠近**的一段连续算式
- 出现"商"字 → 除法按**整数商**算（竖式除法的商）

⚠️ **必须取整段算式**，不能只取第一个 `A op B`：
`24 + 6 × 5` 若只取 `24 + 6` 会算成 30（正确是 54）。
括号也要一起取：`(36 + 54) ÷ 6`。

### 1.2 算

用 `Decimal` 而不是 float（`0.1 + 0.2 != 0.3` 会咬人）。
`eval_arith()` 先用白名单正则 `[\d\s\.\+\-\*/\(\)]+` 卡住，再把数字字面量替换成 `D('...')` 后 `eval`。

### 1.3 比对

- 复算值 vs `a:` 指向的选项文本 → 不一致 = 下标写错
- 复算值必须**出现在选项集合里** → 否则选项集合本身写错

### 1.4 什么题不能复算（必须跳过，否则误报）

| 类型 | 例子 | 原因 |
|---|---|---|
| **估算题** | 「估算 302 × 21，最合适的结果是（　）」 | 选项是**估算值**（6000），精确复算得 6342，不相等才是对的 |
| 概念/判断题 | 「余数必须比除数小」 | 没有算式 |
| 多解/信息不足题 | 「人数相同…多几棵」 | 信息不足时本就不该有唯一数值答案 |
| 步骤描述型选项 | 「25 × 4 ÷ 5 + 18，先算 25 × 4」 | 选项是文字描述 |

### 1.5 选项本身就是算式时——换一条路

题干是「下面各式中，**积是 2400** 的是（　）」，选项是 `'40 × 60'`、`'50 × 40'`…
题干里没有算式，1.1 的路子用不上。改用**逐个复算选项**：

```
目标值 = 从题干里取（且必须紧挨着「（　）」，即"被问的那个量"）
命中 = [i for i, o in enumerate(opts) if eval(o) == 目标值]
若 len(命中) == 1 且 命中[0] != a  →  下标写错
```

⚠️ **目标值必须是"被问的量"**：
「一个数除以 15，**商是 6**，**余数最大**是（　）」——问的是余数不是商，
拿"商是 6"去比对选项 `['5','6','14','15']` 会误报。
判据：目标值与 `（　）` 之间只隔 0~3 个字（允许"的/是"）。

## 二、L3：答案 × 解析 交叉校验

`a:`（答案下标）与 `why:`（解析）是**分别书写**的字段，手误就会打架
（答案写 168°、解析写 180°）。

### 2.1 ⚠️ 不要用"取最后一个 `= 数字`"

这是最直觉的做法，也是**错的**。实测反例：

```
'892 ÷ 22 = 40……12，验算 22 × 40 = 880，880 + 12 = 892。'
   ↑ 答案 40        ↑ 中间量      ↑ 验算      ↑ 最后一个等号 → 误判
'425 ÷ 25 = 17。先看前两位 42，42 ÷ 25 商 1，余 17 落下 5 得 175，175 ÷ 25 商 7。'
   ↑ 答案 17                                        ↑ 最后一个等号 → 误判
```

实测 178 道题里这种误报 **17 处**。原因：等号后面可能是**中间步骤**、**验算**、**公式**。

### 2.2 改用语义分路（实测零误报）

#### ▸ 数值型答案（选项本身是一个数）

- **N1 结论数值一致**：解析若明确写出结论
  （`答案是 X` / `结果是 X` / `商是 X` / `所以……是 X`），必须等于答案
- **N2 答案必现**：答案的数值必须出现在解析里，否则说明解析在讲另一个数 → 下标多半错了
  - 中文数字表述也算命中（答案 `2` ↔ 解析"两位小数"）
- **N3 箭头结论**：解析用 `→` 指出的**最终结果**必须等于答案。
  箭头在课件里专表"算到这里"，比等号可靠得多：

  ```
  '25 × 4 = 100，再添 1 个 0 → 1000'    → 箭头结论 1000 == 答案 1000 ✅
  '480 × 25 = 48 × 25 × 100，再添两个 0 → 12000' → ✅
  ```

  ⚠️ 但箭头也可能是**举例**：`'如 0.123 → 1.23'`。
  判据：**箭头值必须是某个选项的值**，否则视为举例，不据此判错。

#### ▸ 定性型答案（选项是一句话）

- **Q1 信息不足族**：答案属"无法确定/不能确定/不一定/信息不足"类时，
  解析**必须**给出理由（`没有给出|未给出|信息不足|条件不足|不一定|取决于|要看`），否则报错。
- **Q2 结论选项一致**：解析末句若**唯一**命中某个选项，该选项必须是正确答案。
  ⚠️ **整个解析里若出现多个选项，说明是在对比说明/逐条罗列**，
  末句提到的那个不一定是所选答案 → 此时不据此判冲突。

  ```
  '表示变化趋势用折线统计图；表示数量的多少用条形统计图。'   ← 对比说明，两个选项都出现 → 跳过
  '第三个角是 105°，有一个钝角，所以是钝角三角形。'            ← 只命中一个 → 判冲突 ✅
  ```

#### ▸ N3 与"添零推导"的区分

`'25 × 4 = 100，再添 1 个 0 → 1000'`：解析里的 100 与答案 1000 是**推导**关系，不是打架。
判据：两个值只差若干个 0，**且**解析里出现"添/补/去 0"的措辞 → 豁免。

### 2.3 ⚠️ 抽数值前先剥 HTML 标签

课件里结论值常写成 `'= <b>168</b>。'`。不剥标签就取不到结论值 → **把对的题误报成错的**。
所有数值抽取统一先过 `re.sub(r'<[^>]+>', '', text)`。

### 2.4 归一化不能把分隔符也删掉

`'3 cm、4 cm、5 cm'` 若连 `、` 一起删 → 变成 `'345'` → 被当成数值 345。
归一化只剥**单位词**，然后要求**整串**匹配 `-?\d+(\.\d+)?` 才算数值。

## 三、校验脚本自身的三个坑（都曾让校验**静默空跑**）

### 3.1 `re.split` 把字段名吃掉

```python
for blk in re.split(r"\n\s*\{q:", body)[1:]:   # ← "q:" 被当作分隔符吃掉了
    qm = re.search(r"q:'((?:[^'\\]|\\.)*)'", blk)   # ← 永远 None！
    if not (qm and om and am and wm): continue       # ← 全部跳过
```

**症状**：校验脚本永远"全部通过 ✅"，但一条都没检查。
**根因**：`{q:` 中的 `q:` 是分隔符的一部分，`split` 后每块以 `'...'` 开头，不再含 `q:`。
**修法**：用**一条正则**同时抽出 q / opts / a / why，别分两步。

```python
ITEM_RE = re.compile(
    r"\{\s*q:'((?:[^'\\]|\\.)*)'\s*,\s*opts:\[(.*?)\]\s*,\s*a:(\d+)\s*,\s*"
    r"why:\s*'((?:[^'\\]|\\.)*)'(?:\s*\+\s*'((?:[^'\\]|\\.)*)')?", re.S)
```

### 3.2 `Pattern.finditer(body, re.S)` —— 第二参数是 `pos`，不是 `flags`

```python
ITEM.finditer(body, re.S)   # ← re.S(=32) 被当成"起始位置"！
```

**症状**：多行 `opts` 数组的题**整块漏匹配**（因为 `.` 默认不跨行），数量对不上却没人发现。
**修法**：`re.compile(..., re.S)` 把 flags 固化进模式，别在调用处传。

### 3.3 校验脚本必须做**植入测试**

校验脚本自己出错时，输出同样是"全部通过 ✅"——**和真的通过一模一样**。
所以每写完一条规则，必须：

1. 往题库里**植入**一处该规则应抓到的错误
2. 跑校验 → **必须报错**
3. 还原 → 必须回到全绿

```bash
cp uX/app.js /tmp/bak.js
python3 - <<'PY'   # 植入：把答案下标改错
import pathlib; p=pathlib.Path('uX/app.js'); s=p.read_text()
p.write_text(s.replace("...opts:[...], a:2,", "...opts:[...], a:0,"))
PY
python3 tests/check_answers.py     # 期望 ❌
cp /tmp/bak.js uX/app.js
python3 tests/check_answers.py     # 期望 ✅
```

**规则设计的验收标准：真值零误报 + 植入必报。**
两条都成立才算这条规则可用；只有"零误报"说明规则可能根本没生效。

Skill 自带的 `scripts/semantic_selftest.py` 已把这一步自动化：它会复制 `check_answers.py` 模板，
先跑一组故意写错的题（必须命中追及前提、单位改写、多解选项、图形模型、steps 矛盾、零的个数、负数结果），
再跑修正版（必须全绿）。修改语义规则后请执行：

```bash
python3 scripts/semantic_selftest.py
```

## 四、"信息不足型陷阱"题（极易写错）

典型题干：「甲、乙两班**人数相同**，甲班植树总数比乙班多，那么（　）」

- 若选项里有「无法确定」→ 答案是它
- 但**如果选项里没有「无法确定」，答案就不能是具体数值**——人数没给，差值算不出来
- 反向陷阱：题干说"人数相同"却给了人数（"每组 4 人"）→ 可以有唯一数值答案

**自动检测**：

```python
same_n = re.search(r'人数相同|同样多|人数一样', q)
given_n = re.search(r'每组\s*\d+\s*人|每班\s*\d+\s*人|\d+\s*人', q)
if same_n and not given_n and re.match(r'\s*[多少]\s*-?\d', opts[a]):
    problems.append('人数相同但未给人数，答案不该是具体差值')
```

⚠️ 旧版只在"选项含『无法确定』"时才查，漏掉了**没有**「无法确定」选项的版本——
实测就是这样漏掉一道真错题。

## 五、L4：题意与建模检查（"算得出"不等于"题目成立"）

L2/L3 只能证明"算式没算错、答案和解析没打架"，**不能证明题干本身可解、结论类型正确**。
一次全量审计中，追及题把两车速度写反后，答案曾改成"无法确定"——
算术上"追不上"没错，但题干问的是"**几小时后**追上"，前提已经矛盾；
正确修法是**改题**（让后车更快），不是换一个兜底答案。

### 5.1 必须优先检查的高危模型

| 模型 | 检查点 | 反例 |
|---|---|---|
| 追及 | 后车必须比前车快；问"几小时追上"时前提必须成立 | 甲 60 在前、乙 45 在后，却问乙几小时追上 |
| 相遇 | 两车相对/相向，速度和与总路程对应 | 把相遇时间写成路程差 ÷ 速度差 |
| 单位改写 | `原数 ÷ 进率 = 改写后的数` | `396000 = 396 万`（应为 39.6 万） |
| 近似数逆向 | 四舍五入到万位：最大 = 近似值 + 4999，最小 = 近似值 − 5000 | 8 万最大写成 79999（应 84999） |
| 数位/计数单位 | 小数点右第一位是十分位，第二位是百分位 | 0.45 中的 4 说成百分位 |
| 图形变换 | 长方形拉成平行四边形：周长不变，**面积变小** | 长 25、宽 12，拉斜后仍算 25×12=300 |
| 图形剪拼 | "沿高剪成两个直角三角形"通常不成立 | 应说"沿对角线剪成两个三角形" |
| 条件完整性 | 两个集合是否重叠、平均数的份数、整数取值条件必须写全 | 45 人参加两组 18/15，未说互不重叠却直接相减 |
| 选项唯一性 | 多个选项在数学上都成立 = 错题 | `0.450` 与 `0.4500` 都等于 `0.45` |
| steps 一致性 | 详细过程不能是另一道题的残留，也不能与答案相反 | 答案"增加 0.7"，过程末步写"减少 0.7" |

### 5.2 自动规则（模板已内置）

`templates/check_answers.py` 的 `check_semantic_rules()` 与
`check_steps_consistency()` 已包含可复用的骨架：

- `check_chase()`：追及方向与"几小时后"问法冲突
- 近似数上下界、万/亿单位改写、小数数位
- "与 X 相等"型选项的数值唯一性
- 一副三角尺拼角、读数中"零"的个数
- 竖式进位是否进入下一步
- 长方形拉成平行四边形、沿高剪三角形等几何前提
- 交集/并集、平均数逆推、整数度数的条件完整性
- `steps` 中的数值和方向结论必须支持声明答案
- 解析/步骤里的简单数值等式自检（如 `0.36 = 0.09`、`0.50 ≠ 0.5`）

这些规则是**数学示例**；其他学科要替换为本科目的模型检查（如物理单位守恒、化学配平、
地理方向约定），但"先验前提，再验数值"的结构不变。

### 5.3 人工复核清单

自动规则不可能覆盖所有语义。每轮交付仍须人工扫一遍：

- [ ] 题干问的是"时间/长度/数量/比较结论"中的哪一种？答案类型是否匹配？
- [ ] 每个数值条件是否足够？有没有隐藏的"互不重叠、人数相同、整数、同一底"等前提？
- [ ] 图形变换/剪拼后，哪些量不变、哪些量变了？不能凭直觉写"等积"。
- [ ] 同一题的多个选项是否可能同时成立？用极端值和反例各试一次。
- [ ] `why` 与 `steps` 是否是**这道题**的过程，而不是上一道题残留？
- [ ] 低年级题是否引入了未学概念（如四年级出现负数结果、五六年级内容）？
