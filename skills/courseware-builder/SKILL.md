# 互动课件生成器

## 何时用

用户要"做一个教学动画 / 互动课件 / 学习演示 / 课堂工具"，希望配套练习、答案与教案。  
覆盖：数学（几何图形、数轴、统计）、物理（受力、运动、电路）、化学（粒子、反应）、  
语文/英语（文本、听说）、地理（地图、地球）、信息科技（算法可视化、编程启蒙）等。

不适用：PPT、录课视频、需要 npm 构建或后端的在线系统（用对应工具链）。

## 交付物规范（固定五件）

```
<课件目录>/
├── index.html      # 主课件：零外部依赖、离线可用，双击即开
├── 教案.md          # 教学设计：目标 / 重难点 / 流程 / 板书 / 常见错误 / 作业与评价
├── README.md        # 使用说明：文件清单、模块结构、课堂用法、打印与投屏说明
├── preview.png     # 首页预览图
└── tests/          # 自检脚本（见"验收"节）
```

**两条交付路径（先选一条）**

| 路径 | 何时用 | 怎么做 |
|---|---|---|
| **A. 单元流水线**（本仓库既有） | 在 `education/primary/grade4_math_2026/` 下做系列单元课件 | 新建 `uN_主题/{meta.json,body.html,app.js}` → `python3 build.py` → 验收产物。详见 `references/pipeline.md` |
| **B. 独立单文件** | 跨学科、一次性、或不想引入构建步骤 | 复制 `templates/lesson-template.html` 改写，改完即生效 |

两条路径的**练习引擎 API 完全一致**（`mountQuizInto` / `renderAnswers` / `bootCourse`），
课件可在两种形态间无痛迁移。

**分档与星级（练习体系默认约定）**

| 档位 | 星级 | 定位 | 答对反馈 |
|---|---|---|---|
| 巩固基础 | ★★★ | 课内随堂练 | 常规解析 |
| 动手操作 | ★★★ | 看图/操作类 | 常规解析 |
| 扩展思维 | ★★★★ | 多一步思考的拓展题 | 「答对啦！」+ 局部点赞 + 单音 |
| **五星浅奥** | ★★★★★ | 两步以上思考（倒推/辨析/分类讨论） | 「**你好棒！**」+ **满屏点赞** + 喜悦琶音 |
| 五星档全对 | — | — | 「**太棒了！**」全屏庆祝（页面级只触发一次） |

- ⚠️ 音效用 **Web Audio 实时合成**、动画用 **DOM + CSS**，**不产生任何外部文件**——
  否则会破坏"零外部依赖、离线可用"这条硬约束。
- ⚠️ 庆祝**不能刷屏**：同屏点赞有上限、横幅同时只有一条、通关庆祝全局去重。
- 星级标签要打在**每一道题**上（`.qstars`），让学生一眼看到难度分层。

**硬约束**

- `index.html` 不引任何外部 CDN / 字体 / JS 库——断网、离线、投影仪、家长手机都要能开。
- 字体用系统中文字体栈；图标用 emoji 或内联 SVG；图形用 SVG（清晰、可选中、易断言）。
- 内置 `@media print`：隐藏导航与按钮、展开答案区，方便教师打印讲评。

## 三条通用原则（贯穿全流程）

### ① 口径先行：先定义，再渲染

动笔画第一行代码之前，先把本课的关键内容**写成明确的一句话定义/规则**，并检查一致性：

- 数学：「量角器内圈 0° 在右端、外圈 0° 在左端；锐角读内圈、钝角读外圈」
- 物理：「斜面上物体下滑：摩擦力方向沿斜面向上」
- 化学：「化学反应中原子种类不变、数目变」

然后核对三条链路**同源一致**：**课件演示 → 练习题干 → 答案解析 → 教案表述**。  
口径不一致是课件最常见也最隐蔽的错误——学生会照着图读出另一个答案，形成错误经验。

### ② 证据优先：能自动验证的，绝不靠肉眼看

| 验收层 | 检查什么               | 怎么做                                  |
| --- | ------------------ | ------------------------------------ |
| 结构层 | 文件齐、零外部依赖、打印样式在    | 脚本扫 `http`/`cdn` 引用；模拟 print 媒体查询    |
| 内容层 | 口径一致、题答一一对应、术语准确   | 脚本比对题干数/答案数/解析数；术语用禁用词表查             |
| **答案层** | **答案本身对不对**（引擎说对不算） | **独立复算**（Python 重算）+ **答案×解析交叉校验**，详见 `references/answers.md` |
| **语义层** | 题干前提、条件完整性、结果类型、选项唯一性、图形变换是否成立 | **模型断言**：追及方向、单位/进率、四舍五入边界、数位、剪拼关系、信息是否足够；`templates/check_answers.py` 的 `check_semantic_rules()` |
| 交互层 | 控件可点、计分正确、重做可用、零报错 | Playwright 点遍所有控件，捕获 error/pageerror |
| 视觉层 | 图形方向/比例/对齐/出框/重叠   | **几何断言**（量坐标算角度）+ 逐模块截图人工复核          |

> **算术正确 ≠ 题意成立。** 追及题里后车更慢却问"几小时后追上"，答案改成"无法确定"仍然是一道坏题；
> 正确修法是改题干。单位改写、近似数边界、小数数位、图形拉斜/剪拼、交集条件、整数取值条件，
> 都必须单独做模型检查。详见 `references/answers.md` 第五、六节。
>
> 视觉层的关键教训：**弧线画反了肉眼很难发现**（弧可能仍在角附近，只是绕了远路），  
> 必须量坐标断言。通用做法见 `references/graphics.md`。  
> **但断言只能验"自洽"，验不了"符合教材约定"**：竖式部分积怎么写、量角器读哪一圈、  
> 条形图 1 格代表几——凡是教材有明确规定的地方，必须**对照教材人工核一次**，  
> 并把约定写进课件顶部的口径说明，再用断言守住"不漂移"。

### ③ 模块化一次成型

- 一个模块一个 section，独立成文件级段落，出问题好定位、好替换、好复用。
- 数据用数组描述，渲染函数**全量重绘**（`clear()` 后重建），不做增量更新。
- 每完成一个模块立刻跑一次该模块的验收，不要攒到最后。

## 流程（按序执行）

1. **定口径**：写清楚本课的定义/规则/术语表（见原则①）。
2. **选模式**：从下面的"可视化模式库"里挑本课要用的模式（`references/patterns.md`）。
3. **搭骨架**：复制 `templates/lesson-template.html`，替换标题/导航/占位模块，先能跑通。
4. **填内容**：按模块推进，每模块自带验收。
5. **配练习**：四档（★★★ 巩固 / ★★★ 动手 / ★★★★ 扩展 / ★★★★★ 浅奥），配答案与解析。
6. **写教案**：目标、重难点、分环节流程、板书、常见错误表、作业与评价。
7. **跑验收**：六层自检（结构 / 内容 / 答案 / 语义 / 交互 / 视觉），几何断言必须全绿。
8. **出预览、写 README**，交付时给出绝对路径与文件清单。

## 可视化模式库（选型速查）

| 模式   | 适用场景           | 实现要点                       | 验收方式          |
| ---- | -------------- | -------------------------- | ------------- |
| 标注图示 | 讲结构、部件、术语      | 静态 SVG + 标注引线；标注放图形**外侧**  | 截图 + 出框/重叠检查  |
| 参数动画 | 讲变化、规律、函数      | 滑块/按钮驱动参数，渲染函数全量重绘         | 几何断言（状态与图形一致） |
| 分步演示 | 讲操作流程（如量角器三步法） | 步骤状态机，每步只高亮一个要素            | 逐步截图 + 步骤数断言  |
| 对比实验 | 讲变量控制、"变了什么"   | 并排子图 + 共享参数 + 单变量差异        | 子图数断言 + 参数一致性 |
| 模拟沙盒 | 讲动态系统（运动、电路）   | 状态机 + 时间步进 + 可调参数          | 状态不变量断言（如守恒量） |
| 互动探索 | 学生自己玩中学        | 拖拽/点击 + 实时反馈               | 交互巡检          |
| 测验引擎 | 巩固与拓展          | 见 `references/pedagogy.md` | 题数/计分/重做一致性   |

**跨模式通用**：任何模式都可以由「参数 → 渲染函数 → 断言」三段构成；  
把"参数"与"渲染"分开，就能同时支持播放动画和拖拽交互，两条路径共用一份图形逻辑。

## 练习与答案（要点）

- 分层**四档 + 星级标注**（推荐）：**★★★ 巩固**（随堂练，覆盖全部口径）/ **★★★ 动手**（操作、读图）/
  **★★★★ 扩展**（拓展题，计算与迁移）/ **★★★★★ 五星挑战**（浅奥思维，需两步以上思考）。
- **难度标识 ≠ 评价目标**：五星题答错是正常的，它的价值在于让学生体验"想不出来"的过程，
  教师借此追问"你卡在哪一步"比直接给答案更有价值。
- **正反馈机制（可选但推荐）**：答对四星/五星题时给正反馈——横幅 + 点赞 + 音效。
  ⚠️ **音效必须用 Web Audio 实时合成**，动画必须用 DOM + CSS，
  否则会破坏"零外部依赖、离线可用"这条硬约束。
  同时要设**同屏上限**、**横幅唯一**、**通关只庆一次**，避免连续答对时刷屏。
- 反馈三段式：**答错**只给可操作的提示（"回到动画 5-1 再看一遍"），**不泄露答案**；  
  **答对**给说理式解析，不只是重复答案。
- **干扰项对应真实的错误想法**（例：内外圈读反 → 选项 65°），不放离谱选项。
- 每组独立计分、独立重做（不刷新整页）；填空答案归一化（"180/180度/180°"）。
- 答案集中在一个折叠区，页尾，便于讲评与打印。

## 常见弯路清单（实战踩过）

| 弯路            | 后果                   | 对策                                 |
| ------------- | -------------------- | ---------------------------------- |
| 图形方向/比例画反     | 图与文字描述矛盾，误导学生        | 几何断言，别靠看（`references/graphics.md`） |
| 口径没先定死        | 课件、题目、答案互相打架         | 原则① + 三条链路同源检查                     |
| 题目数据硬编码在 HTML | 增删题要改多处，答案容易漏        | 数据数组驱动渲染，答案由同一份数据生成                |
| 一个文件写到底       | 后期难维护、难复用给别的课        | 模板化分层：工具层 / 渲染层 / 引擎层 / 数据层        |
| 一次性写完再调试      | 报错难定位，改一处坏三处         | 模块化推进 + 每步验收                       |
| 断言前没回到确定状态    | 残留动画覆盖滑块值，断言测的不是设定状态 | 视觉层断言前先 `reload()` 再设参数            |
| 改了内容忘同步教案     | 交付物自相矛盾              | 教案与答案从同一份数据生成                      |
| 追求动画炫技        | 课堂时间被动画吃掉            | 动画服务教学目标，每个动画配一句"这个动画让你看出什么"       |
| 同一档的题目分两次挂载 | 后挂载的填空题**覆盖**先挂载的选择题，页面看着正常却少了半数题 | 一次挂载 choice+fill；内容层断言"显示题数 == 标称总题数" |
| 竖式部分积写成"左移前的数字"再左移 | 竖式里按列相加对不上（290+145≠1740），被判为"算法是错的" | 部分积写**左移后的完整积**（145×1×10 = **1450**）；"位置自洽"≠"与教材一致" |
| 逐步演示把最终答案预先填好 | 动画只剩高亮在动，学生看不到推导过程，等于假动画 | 未算出的格子留空；断言"第 0 步不得出现结果数字" |
| 讲解文字里的位名与格子不一致 | 部分积左移后仍说"在个位写"，学生落错位 | 位名按**结果实际所在列**算（部分积左移 i 位 → 列 = j + i） |
| **答案下标写错但测试全绿** | 引擎与题目数据同源，两者一起错时自洽性测试发现不了 | 另加一道"**独立复算**"验收：用 Python 从题干解析算式独立算出答案，与 `a:` 指向的选项比对 |
| **校验脚本自己空跑**（永远"全部通过 ✅"） | `re.split(r"\n\s*\{q:", ...)` 把 `q:` 当分隔符吃掉了，后续 `search(r"q:'...'")` 恒为 `None` | **用一条正则同时抽 q/opts/a/why**，别分两步；每条规则都要做**植入测试**（植入错→必报，还原→全绿） |
| **`Pattern.finditer(body, re.S)` 静默漏配** | `Pattern` 的第二参数是 `pos` 不是 flags，`re.S` 被当成起始位置 | flags 写进 `re.compile(..., re.S)`；解析条数要与"粗略计数"**对账** |
| **用"最后一个等号"抽答案结论，误报一片** | 等号后面可能是中间步骤/验算/公式（实测 178 题误报 17 处） | 按语义分路：结论措辞 + 答案必现 + `→` 箭头结论；抽数值前先剥 `<b>` 标签 |
| **页面出现 `[object HTMLInputElement]`** | 把 DOM 元素当字符串拼接（`lab.textContent = a + ' + ' + B`，a 是元素不是值） | 拼接前一律先取 `.value`；**渲染后扫 DOM 叶子节点文本**，命中 `[object ` 即失败 |
| 分步演示的"结论态"不可达 | `step` 夹在 `length-1`，渲染却判断 `>= length` | 统一约定 `step` 可取到 `length`（结论态），并加"结论可达性"回归断言 |
| 共享 helper 覆盖宿主 svg 的 viewBox | helper 擅自改坐标系，把同图其他元素挤出画布 | helper 不得改宿主 viewBox；先判断再设置 |
| **题干前提不成立，却用"无法确定"兜底** | 学生看到的是一道自相矛盾的题；答案换了也救不回题意 | 先验模型前提（如追及方向）；前提不成立就**改题**，不要只改答案 |
| **只验算术，不验单位/数位/图形关系** | `396000 = 396 万`、`0.45` 的 4 说成百分位、长方形拉斜后仍按长×宽算面积 | L4 语义断言：单位进率、小数数位、图形变换后的不变量与变量 |
| **题目信息不足或选项多解** | 两个兴趣小组是否重叠没说、去掉一个数却没给剩余平均数、两个选项都等于目标值 | 写全条件；用反例/极端值检查选项唯一性；不唯一就改题 |
| **steps 是另一道题的残留** | 答案 10 只，详细过程却算出 8 只；答案"增加"，过程写"减少" | `check_steps_consistency()`：步骤中的答案数值与方向结论必须支持声明答案 |
| 改了 skill 忘记同步 | Codex 用的还是旧版本 | 收尾固定跑 `install.sh` + `scripts/self_check.py` |

## 自迭代：让 skill 随任务自动变好

**这个 skill 是活的。** 每次用它做课件时，若出现下列任一情况，
**必须在本次任务收尾前把经验写回 skill**，否则下一个任务会重蹈覆辙。

### 触发条件（命中即更新）

1. 踩到 skill 未覆盖的坑（图形画反、题目丢失、口径打架、打印错位……）
2. 发现流程缺一步（少一次验收、少一件交付物）
3. 模板/脚本有缺陷（复制模板跑不起来、断言误报或漏报、**校验脚本静默空跑**）
4. 用户纠正了你的做法
5. 仓库共享资产（引擎/样式）被改动，影响了已有课件

### 更新动作（按影响面选择，但 1、2 必做）

| 沉淀位置 | 什么时候写 |
|---|---|
| `LESSONS.md` 经验沉淀表 | **每次必写**：现象 → 根因 → 预防规则 → **回归测试出处** |
| `SKILL.md` 弯路表 / 原则 | 经验可上升为通用规则时 |
| `references/*.md` | 属于某专题（绘图、模式、练习、流水线）的知识 |
| `templates/visual_test.py` | **图形/交互类坑必须加断言**，让同类问题无法再复发 |
| `templates/lesson-template.html` | 模板层缺陷（少功能、跑不起来） |
| `CHANGELOG.md` | 每次改 skill 都要记一笔（版本号 + 改了什么 + 为什么） |

### 收尾动作（固定三步）

```bash
# ⚠️ 真源在**仓库里**：education/skills/courseware-builder/
#    ~/.codex/skills/courseware-builder/ 是**安装副本**，只读。
#    直接改安装副本 → 下次 install.sh 会把你的改动**覆盖掉**（上一轮就这么丢过一轮工作）。
cd education/skills/courseware-builder
bash install.sh                  # 同步到 ~/.codex/skills（否则本次修改不会被 Codex 发现）
python3 scripts/self_check.py    # skill 自身健康检查（结构/引用/语法/记忆/漂移）
```

`self_check.py` 的"漂移检测"会告诉你两边是否一致——**不一致就是走错了目录**。

### 改校验脚本的额外要求

改任何**校验/断言**脚本（含课件里的 `check_answers.py`、`audit.py`）后，
必须做**植入测试**：植入一处该规则应抓到的错 → 脚本**必须报错**；还原 → 必须回到全绿。
原因：校验脚本自己出错时，输出同样是"全部通过 ✅"，和真的通过**一模一样**。
详见 `references/answers.md` §三。

`self_check.py` 检查：SKILL.md 引用到的文件是否存在、脚本能否编译、模板是否含关键标记、
LESSONS 每条是否注明回归测试、**以及"仓库源 vs 已安装副本"是否一致**——
后者能防止"改了但忘了同步"。

### 铁律

- **只记录已验证的结论**：没复现过、没跑过断言的，不许写进 LESSONS。
- **每条经验必须配一个可执行的回归测试**：否则只是许愿，下次照踩。
- **先修 bug，再写经验**：顺序是「定位根因 → 修复 → 加断言 → 写经验 → 同步安装」。

## 配套资源

- `templates/lesson-template.html` —— 可直接运行的骨架：工具层（含统一弧线/坐标约定）+ 练习引擎 + 答案区 + 打印样式。
- `templates/visual_test.py` —— 四层自检脚本模板（几何断言 + 交互巡检 + 截图 + 结构/内容检查）。  
  注意它内置了一个易踩的细节：**几何断言前会 reload 页面**，否则交互巡检触发的残留动画会覆盖滑块状态。
- `references/answers.md` —— **答案与题意校验手册**：L1 自洽 / L2 独立复算 / L3 答案×解析交叉 / L4 语义与建模，
  含追及前提、单位/近似数、图形变换、信息充分性、选项唯一性、steps 一致性与**植入测试**规范。
- `templates/check_answers.py` —— 可直接复用的**答案与语义校验器模板**（独立复算 + 解析交叉 + 模型断言），
  拷进 `tests/` 后按课件改档位名、字段名、年级约束与学科规则即可。
- `scripts/semantic_selftest.py` —— 校验器自身的**植入测试**：故意放错题必须报红，换成修正题必须全绿；
  `self_check.py` 会自动运行它，防止校验规则静默失效。
- `references/graphics.md` —— 绘图正确性手册：坐标与角度约定、弧线方向、出框与重叠、验证方法。
- `references/patterns.md` —— 可视化模式库详解与各学科适配建议。
- `references/pedagogy.md` —— 练习设计、答案反馈、教案结构的方法要点。
- `references/checklist.md` —— 交付前逐项打勾的自检清单。
- `references/pipeline.md` —— 本仓库 `grade4_math_2026` 单元流水线：目录约定、meta 字段、build.py 用法、共享引擎 API 清单。
- `LESSONS.md` —— **经验沉淀表**（自迭代记忆）：每条经验都带根因、预防规则与回归测试出处。
- `CHANGELOG.md` —— skill 自身的版本与变更记录。
- `install.sh` —— 把 skill 同步到 `~/.codex/skills/<name>/`，**Codex 靠扫描该目录发现技能**。
- `scripts/self_check.py` —— skill 自身健康检查（含"仓库源 vs 安装副本"漂移检测）。

## 安装与被 Codex 发现

Codex 通过扫描 `~/.codex/skills/` 发现技能（其下每个含 `SKILL.md` 的子目录即可），
仓库里的 skill **不会**被自动发现，必须安装一次：

```bash
bash education/skills/courseware-builder/install.sh     # 幂等，可重复执行
```

安装后新开一个 Codex 会话即可使用；当前会话需重启才会加载。
安装副本是"只读快照"：**永远改仓库里的真源**，改完重跑 `install.sh` 同步。
